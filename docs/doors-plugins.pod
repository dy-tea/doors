=head1 NAME

doors-plugins - writing layout plugins for the doors Wayland compositor

=head1 DESCRIPTION

doors can load shared libraries at runtime that register additional
I<layouts>. A layout decides how tiled windows are arranged on a desktop
and how focus and swaps move between them.

A plugin is a shared library that exports a single global structure
named C<doors_plugin>:

	struct doors_plugin_t {
		uint32_t api_version;                // must be DOORS_PLUGIN_API_VERSION
		const char *name;                    // plugin name, for logging and listing
		const layout_impl_t *const *layouts; // NULL-terminated list of layouts
	};

Every element of I<layouts> is a C<layout_impl_t>. See C<include/layout/layout.h>
All callbacks are optional (set them to C<NULL> when not needed), except
that a layout without I<arrange> will never move windows.

=head2 Layout settings and commands

A layout can expose configuration and subcommands of its own, and doors
publishes both through C<doorsctl layout>:

	doorsctl layout -l                 # list layouts
	doorsctl layout strip -l           # list one layout's options
	doorsctl layout strip gap 20       # write a setting
	doorsctl layout strip gap          # read it back
	doorsctl layout strip focus_first  # run a command

I<settings> is an array of C<setting_t> with I<settings_count>
entries, and I<commands> is a NULL-terminated array of
C<command_t>; both are described in C<include/settings.h>.
A setting points at storage the layout owns, so it is read and written
in place:

	static int strip_gap;

	static const setting_t strip_settings[] = {
		{
			.name = "gap",
			.type = SETTING_INT,
			.ptr = &strip_gap,
			.min = 0,
			.max = 200,
			.fmt = "%d\n",
			.flags = SETTING_COMMIT,
		},
	};

	static const command_t strip_commands[] = {
		{"focus_first", "layout strip focus_first", strip_focus_first},
		{NULL, NULL, NULL},
	};

A command receives the remaining C<ipc_args_t> arguments and answers with
C<ipc_ok>, C<ipc_okf> or C<ipc_fail>. Setting and command names have to
be unique within a layout, and a layout that reuses a name is refused at
registration.

The values of the settings table are recorded when the layout is
registered, so C<doorsctl layout strip reset> puts them back. Implement
C<reset> for any state the table does not describe; it is called by the
unnamed form of the command.

=head2 Loading plugins

	doorsctl plugin load /path/to/plugin.so
	doorsctl plugin list

Put C<doorsctl plugin load ...> in your I<doorsrc> to load plugins at
startup; plugins can also be loaded at any time at runtime. A plugin must
export C<doors_plugin>, have the same API version as the running compositor
and have a unique name.

=head2 Writing a layout

The minimal useful layout implements I<arrange>, I<focus> and I<swap>.
Windows on a desktop live in a tree (C<d->root>); for a tree-agnostic
layout, collect the tiled leaves, compute a box for each one and write
the geometry:

	static void my_arrange(output_t *m, desktop_t *d, struct wlr_box available) {
		node_t **nodes = NULL;
		const int count = collect_tiled_leaves(d, &nodes);
		// ... divide `available` into `count` boxes ...
		for (each node) {
			c->tiled_rectangle = inner;      // box minus borders
			c->arranged_rectangle = inner;
			node_set_pending_rectangle(n, outer);
			n->output = m;
			node_set_dirty(n);
		}
		free(nodes);
	}

Per-desktop state can be stored with C<layout_state_get()>. A plugin does not
know the numeric id its layout was registered under, so it can pass its
C<layout_impl_t> to C<layout_state_get_impl()> instead; C<layout_id_for()>
returns the id itself. Every layout owns one state per desktop. The slot is
not destroyed by I<leave> unless the layout drops it.

Per-client state is stored the same way with C<client_layout_state_get()> and
C<client_layout_state_get_impl()>. Clients start without state, so
I<client_created> is the place to attach it; it is dropped when the client is
freed.

=head2 Building a plugin

Plugins are built against the doors headers, all symbols are resolved from the
running compositor using C<dlopen()>. From the doors repository root:

	cc -shared -fPIC -o strip.so strip.c -DWLR_USE_UNSTABLE \
		-Iinclude -I/usr/include/pixman-1 -I/usr/include/wlroots-0.21 \
		$(pkg-config --cflags wayland-server glib-2.0)
