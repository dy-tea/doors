=head1 NAME

doors-plugins - writing layout plugins for the doors Wayland compositor

=head1 DESCRIPTION

doors can load shared libraries at runtime that register additional
I<layouts>. A layout decides how tiled windows are arranged on a desktop
and how focus and swaps move between them.

A plugin is a shared library that exports a single global structure
named C<doors_plugin>:

	struct doors_plugin_t {
		uint32_t api_version;                // must be DOORS_PLUGIN_API_VERSION
		const char *name;                    // plugin name, for logging and listing
		const layout_impl_t *const *layouts; // NULL-terminated list of layouts
	};

Every element of I<layouts> is a C<layout_impl_t>, the same abstraction
the built-in layouts use:

	typedef struct layout_impl_t {
		const char *name; // unique layout name, e.g. "strip"

		// called when an automatic arrange occurs (e.g. output size changes)
		void (*arrange)(output_t *m, desktop_t *d, struct wlr_box available);

		// called when focus_node is called
		void (*on_focus)(output_t *m, desktop_t *d, node_t *n);

		// called when the focus bind is executed (returns true if focus succeeded)
		bool (*focus)(desktop_t *d, direction_t dir);

		// called when the swap bind is executed (returns true if swap succeeded)
		bool (*swap)(output_t *m, desktop_t *d, direction_t dir);

		// called when the layout becomes active on a desktop, to adopt the toplevels
		void (*enter)(output_t *m, desktop_t *d);

		// called when the layout stops being active, so it can drop its per-desktop state
		void (*leave)(output_t *m, desktop_t *d);

		// called when a new client is mapped on a desktop using this layout
		// (returns true if the layout took over the client)
		bool (*init_client)(output_t *m, desktop_t *d, client_t *c);

		// called after a new client has been placed on the desktop and
		// before it is focused
		void (*client_mapped)(output_t *m, desktop_t *d, client_t *c,
			bool focused);

		// called before a client is removed from the desktop
		void (*client_unmapped)(output_t *m, desktop_t *d, client_t *c);

		// called after a client was removed and the desktop rearranged;
		// return true when the layout picked the next focus itself
		bool (*focus_after_unmap)(output_t *m, desktop_t *d, node_t *removed);

		// called after a client changes state (fullscreen, maximized, minimized,
		// tiled/floating) and before the desktop is rearranged
		void (*on_client_state)(output_t *m, desktop_t *d, node_t *n,
			client_state_t old_state);

		// called when the resize bind runs; return true if the layout resized
		// the focused toplevel itself, false to resize the split tree
		bool (*resize)(output_t *m, desktop_t *d, direction_t dir, double delta);

		// true when this layout places floating clients itself
		bool (*places_floating)(desktop_t *d, client_t *c);

		// true when the layout wants node `n` shown while its desktop is
		// visible (NULL shows every node)
		bool (*wants_visible)(const desktop_t *d, const node_t *n);

		// true when `c` should be drawn without a border
		bool (*borderless)(const desktop_t *d, const client_t *c);

		// true when `c` counts as maximized even though the client does not
		// report it
		bool (*reports_maximized)(const desktop_t *d, const client_t *c);

		// window gap around the layout's tiled leaves; NULL uses the global one
		int (*window_gap)(const desktop_t *d);

		// allowed edges for a pointer resize of `n`; return false to use the
		// split tree's edges
		bool (*resize_edges)(const desktop_t *d, const node_t *n,
			uint32_t *edges);

		// called when a pointer resize starts; return true when the layout owns
		// the drag and write the size the drag starts from to `initial`
		bool (*pointer_resize_begin)(output_t *m, desktop_t *d, node_t *n,
			double *initial);

		// called with the pointer delta since the grab started; return true
		// when the layout handled it
		bool (*pointer_resize_update)(output_t *m, desktop_t *d, node_t *n,
			double delta);

		// fraction of the viewport that has to be scrolled to bring `n` into
		// view, used by focus follows mouse
		double (*focus_scroll_distance)(const desktop_t *d, const node_t *n);

		// number of fingers the layout consumes for panning, 0 for none
		uint32_t (*pan_fingers)(const desktop_t *d);

		// pan the layout's view; return true when the layout handled it
		bool (*pan_update)(output_t *m, desktop_t *d, double delta);

		// finish a pan, snapping the layout's view
		bool (*pan_end)(output_t *m, desktop_t *d);

		// settings exposed through `doorsctl layout <name> <setting>`
		const setting_t *settings;
		size_t settings_count;

		// commands exposed through `doorsctl layout <name> <command>`,
		// terminated by a NULL name
		const command_t *commands;

		// restores values the settings do not describe, on
		// `doorsctl layout <name> reset`
		void (*reset)(void);

		// true if the layout only shows a single toplevel at once
		bool single_visible;
	} layout_impl_t;

All callbacks are optional (set them to C<NULL> when not needed), except
that a layout without I<arrange> will never move windows.

=head2 Layout settings and commands

A layout can expose configuration and subcommands of its own, and doors
publishes both through C<doorsctl layout>:

	doorsctl layout -l                 # list layouts
	doorsctl layout strip -l           # list one layout's options
	doorsctl layout strip gap 20       # write a setting
	doorsctl layout strip gap          # read it back
	doorsctl layout strip focus_first  # run a command

I<settings> is an array of C<setting_t> with I<settings_count>
entries, and I<commands> is a NULL-terminated array of
C<command_t>; both are described in C<include/settings.h>.
A setting points at storage the layout owns, so it is read and written
in place:

	static int strip_gap;

	static const setting_t strip_settings[] = {
		{
			.name = "gap",
			.type = SETTING_INT,
			.ptr = &strip_gap,
			.min = 0,
			.max = 200,
			.fmt = "%d\n",
			.flags = SETTING_COMMIT,
		},
	};

	static const command_t strip_commands[] = {
		{"focus_first", "layout strip focus_first", strip_focus_first},
		{NULL, NULL, NULL},
	};

A command receives the remaining C<ipc_args_t> arguments and answers with
C<ipc_ok>, C<ipc_okf> or C<ipc_fail>. Setting and command names have to
be unique within a layout, and a layout that reuses a name is refused at
registration.

The values of the settings table are recorded when the layout is
registered, so C<doorsctl layout strip reset> puts them back. Implement
C<reset> for any state the table does not describe; it is called by the
unnamed form of the command.

=head2 Loading plugins

	doorsctl plugin load /path/to/plugin.so
	doorsctl plugin list

Put C<doorsctl plugin load ...> in your I<doorsrc> to load plugins at
startup; plugins can also be loaded at any time at runtime. A plugin must
export C<doors_plugin>, have the same API version as the running compositor
and have a unique name.

=head2 Writing a layout

The minimal useful layout implements I<arrange>, I<focus> and I<swap>.
Windows on a desktop live in a tree (C<d->root>); for a tree-agnostic
layout, collect the tiled leaves, compute a box for each one and write
the geometry:

	static void my_arrange(output_t *m, desktop_t *d, struct wlr_box available) {
		node_t **nodes = NULL;
		const int count = collect_tiled_leaves(d, &nodes);
		// ... divide `available` into `count` boxes ...
		for (each node) {
			c->tiled_rectangle = inner;      // box minus borders
			c->arranged_rectangle = inner;
			node_set_pending_rectangle(n, outer);
			n->output = m;
			node_set_dirty(n);
		}
		free(nodes);
	}

Per-desktop state can be stored with C<layout_state_get()>. A plugin does not
know the numeric id its layout was registered under, so it can pass its
C<layout_impl_t> to C<layout_state_get_impl()> instead; C<layout_id_for()>
returns the id itself. Every layout owns one state per desktop. The slot is
not destroyed by I<leave> unless the layout drops it.

=head2 Building a plugin

Plugins are built against the doors headers, all symbols are resolved from the
running compositor using C<dlopen()>. From the doors repository root:

	cc -shared -fPIC -o strip.so strip.c -DWLR_USE_UNSTABLE \
		-Iinclude -I/usr/include/pixman-1 -I/usr/include/wlroots-0.21 \
		$(pkg-config --cflags wayland-server glib-2.0)
